# Форматы копий и CSV

[Документация](README.md) · [Как сохранить и восстановить копию](USER_GUIDE.md#копии-и-восстановление) · [English overview](#english-overview)

Это техническая справка для разработчиков. Копия переносит данные независимо от
схемы Room: это JSON-снимок в одном из двух контейнеров, а не файл базы данных.
Кодек проверяет и преобразует снимок, но не записывает его в хранилище.

| Файл | Контейнер | Защита |
| --- | --- | --- |
| `.otmbackup` | `OTMB1` | Шифрование паролем, проверка целостности через AES-GCM. Вариант по умолчанию. |
| `.otmplain` | `OTMP1` | Открытый JSON с контрольной суммой. Не зашифрован и не защищён от подделки. |

Оба файла создаются через системный выбор документа с MIME-типом
`application/octet-stream`. Формат определяется по содержимому, а не по имени,
расширению или MIME. Переименование файла не меняет защиту.

## Зашифрованный контейнер OTMB1

Числа записаны в big endian. Заголовок занимает 42 байта.

| Смещение | Размер, байт | Содержимое |
| --- | --- | --- |
| 0 | 5 | ASCII `OTMB1`, hex `4f544d4231` |
| 5 | 1 | Бинарная версия `01` |
| 6 | 4 | Число итераций PBKDF2: `310000`, hex `0004baf0` |
| 10 | 16 | Случайная соль |
| 26 | 12 | Случайный nonce |
| 38 | 4 | Неотрицательная длина JSON в байтах UTF-8 |
| 42 | Длина JSON | Зашифрованные данные |
| После данных | 16 | Тег аутентификации GCM |

Версия 1 задаёт PBKDF2-HMAC-SHA256, ключ AES 256 бит, `AES/GCM/NoPadding`
и 128-битный тег. Допустимы только 310 000 итераций; произвольное значение
из входного файла не выполняется. Все 42 байта заголовка входят в AAD.
Для другого алгоритма нужна новая версия контейнера.

Соль и nonce запрашиваются у `SecureRandom` последовательно: 16 и 12 байт.
В рабочем коде нужен криптографически надёжный генератор; фиксированный
используется только для тестовых векторов.

Пароль передаётся как `CharArray` в `PBEKeySpec`, без преобразования в `String`.
Кодек очищает свою копию пароля, выведенный ключ и временный массив открытых
данных. Входной массив принадлежит вызывающему коду, который очищает его сам.
Внутренние копии JVM и криптографического провайдера полностью контролировать нельзя.

Для **новых** копий Android-приложение требует 12 Unicode code points минимум
и 1024 байта UTF-8 максимум. Пробелы не обрезаются, Unicode не нормализуется.
Эта политика не меняет формат: старые файлы с короткими паролями читаются.

## Открытый контейнер OTMP1

Создаётся отдельным действием после предупреждения. Пароля, шифрования, MAC
или цифровой подписи нет. Любой получатель может изменить данные и пересчитать
контрольную сумму. **SHA-256 здесь обнаруживает случайное повреждение,
но не подтверждает подлинность.**

Заголовок — 82 ASCII-байта, без BOM. Переводы строк — одиночный LF (`0a`).

| Смещение | Размер, байт | Содержимое |
| --- | --- | --- |
| 0 | 6 | ASCII `OTMP1` и LF, hex `4f544d50310a` |
| 6 | 1 | Версия: ASCII `1` (`31`), не бинарный `01` |
| 7 | 1 | LF |
| 8 | 8 | Длина JSON в байтах UTF-8: восемь строчных hex-цифр с ведущими нулями |
| 16 | 1 | LF |
| 17 | 64 | `SHA-256(payload)` в строчном hex |
| 81 | 1 | LF |
| 82 | Объявленная длина | Открытый JSON-снимок |

Сумма считается только по точным байтам JSON. Заголовок не входит в расчёт;
переводы строк и Unicode не преобразуются. Размер файла должен быть ровно
`82 + объявленная длина`. Неправильные разделители, hex, длина, сумма,
усечение или лишние байты отклоняются. Сжатия нет.

У обоих контейнеров одинаковые правила JSON. Обычный JSON без заголовка `OTMP1`
не принимается. Старое приложение, которое читает только `OTMB1`, не откроет
`.otmplain`. Неверный пароль или тег `OTMB1` никогда не приводят к повторному
чтению как открытого файла.

## JSON-схема версии 2

Все ключи обязательны, включая `activeEntry: null`. Запись компактная, без BOM;
элементы списков сохраняют порядок. Порядок ключей при чтении может отличаться.
Ниже тот же снимок с отступами для удобства чтения:

```json
{
  "schemaVersion": 2,
  "projects": [{
    "id": "a1234567-89ab-4cde-8fab-0123456789ab",
    "name": "Работа",
    "colorArgb": -15584170,
    "createdAtUtcMillis": 0,
    "archivedAtUtcMillis": null,
    "isDefault": false
  }],
  "entries": [{
    "id": "b1234567-89ab-4cde-8fab-0123456789ab",
    "projectId": "a1234567-89ab-4cde-8fab-0123456789ab",
    "note": "",
    "zoneId": "Europe/Moscow",
    "source": "TIMER"
  }],
  "segments": [{
    "id": "c1234567-89ab-4cde-8fab-0123456789ab",
    "entryId": "b1234567-89ab-4cde-8fab-0123456789ab",
    "projectId": "a1234567-89ab-4cde-8fab-0123456789ab",
    "startUtcMillis": 0,
    "durationMillis": 1000
  }],
  "activeEntry": null,
  "preferences": {
    "theme": "SYSTEM",
    "dynamicColor": true,
    "privacyMode": true,
    "dailyGoalMinutes": 480
  }
}
```

### Поля и проверки

- `projects` содержит имя, ARGB-цвет, даты создания и архивации.
  Служебный «Без проекта» имеет UUID `00000000-0000-4000-8000-000000000001`,
  имя хранения `@default`, `isDefault: true` и не архивируется. Это не
  пользовательская настройка проекта по умолчанию.
- `entries` хранит проект, заметку, исходный `ZoneId` и источник:
  `TIMER`, `MANUAL` или `IMPORT`.
- `segments` хранит закрытые интервалы. Время начала — Unix epoch UTC
  в миллисекундах; длительность — строго положительное целое число миллисекунд.
  Проект интервала должен совпадать с проектом записи.
- Все ID и ссылки — полные UUID вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.
  Сокращения и пробелы не допускаются. Регистр сохраняется; ссылка должна
  совпадать с текстом объявленного ID. Повторяющиеся ID и отсутствующие ссылки
  отклоняются. Проверка полной формы UUID не зависит от регистра.
- Пустые имена и заметки допустимы на уровне формата и не преобразуются.
  Это не отменяет более строгих правил редактора приложения.
- Неизвестные ключи, значения `source`/`state`, неправильные типы,
  невалидный UTF-8 или `ZoneId`, дробные машинные целые и лишние JSON-токены
  отклоняются. Переполнение конца интервала или суммы длительностей записи
  тоже считается ошибкой.

### Незавершённая запись и настройки

`activeEntry` — `null` или объект с `entryId`, `projectId`, `state`.
Допустимы `RUNNING`, `PAUSED`, `NEEDS_REVIEW`, но не `IDLE`.
При импорте `RUNNING` становится `NEEDS_REVIEW`; другие состояния сохраняются.
Открытый интервал, монотонные часы и номер загрузки устройства не переносятся.
Время между созданием копии и импортом не добавляется, рабочая сессия
автоматически не запускается.

`preferences` переносит `theme` (`SYSTEM`, `LIGHT`, `DARK`), `dynamicColor`,
`privacyMode` и `dailyGoalMinutes` (15–1440). Язык, выбранный локально проект
по умолчанию и настройка Live Updates в снимок не входят.

### Совместимость с версией 1

Читатель поддерживает JSON `schemaVersion: 1`; писатель всегда создаёт версию 2.
Для отсутствующих полей используются стандартный цвет, дата создания `0`,
отсутствие архивации и настройки SYSTEM/dynamic/privacy с целью 480 минут.
Старое имя служебного проекта приводится к `@default`.

При объединении проекта версии 1 сравнивается представленное в нём имя,
а не подставленные цвет и даты. Для служебного UUID дата создания на конкретном
устройстве не создаёт конфликт; остальные правила версии 2 сохраняются.
Замена сохраняет дату из копии.

## Чтение и восстановление в Android

`backupFormat(uri)` ограниченно читает выбранный `content://` документ:
проверяет сигнатуру, версию и длину контейнера, для `OTMP1` — также сумму.
Это ещё не проверка JSON или GCM-тега. `inspectBackup` читает файл заново
и проверяет его полностью. `expectedFormat` отклоняет смену формата провайдером
между предупреждением и просмотром.

До применения предпросмотр не меняет историю. Конфликт, блокировка таймером,
отмена до коммита или откат позволяют повторить попытку. Успешный коммит
потребляет предпросмотр, даже если последующее обновление настроек или системных
элементов не завершилось.

Merge проверяет конфликты и итоговый предел проектов в одной транзакции до
вставок. Replace очищает и заполняет таблицы Room в одной отменяемой транзакции
порциями. Отмена откатывает весь граф базы, но успешная замена необратима.

Room и DataStore не имеют общей транзакции. Вместе с заменой Room сохраняет
устойчивую запись целевых настроек. Затем приложение применяет DataStore и
копию privacy-настройки для системных элементов. Незавершённый шаг повторяется
после запуска; поздние ручные изменения идут через тот же порядок операций.
Поэтому старое восстановление не должно перезаписать новый выбор.

Если база уже сохранена, результат остаётся `RestoreResult.Applied` с
`preferencesPending: true`, а не ошибкой импорта базы. Предпросмотр повторно
не применяется. Настройки могут вернуть `APPLIED_PENDING_RECOVERY`, сохранив
журнал для повтора; успешное согласование возвращает `APPLIED` и удаляет запись.
`reconcilePendingPreferences()` позволяет повторить этот шаг отдельно.
Пока системная копия privacy-настройки не записана, названия могут быть видны.

Перед экспортом приложение завершает ожидающие настройки и последовательно
читает DataStore и снимок Room. Ошибка чтения или согласования отменяет создание
копии до записи файла. При ошибке или отмене временные буферы очищаются,
частичный снимок не выдаётся.

## Лимиты и ошибки

| Ограничение | Android-приложение | Базовый кодек |
| --- | --- | --- |
| Весь контейнер | 4 МиБ | 50 МиБ (52 428 800 байт) |
| Проекты, записи и интервалы | До 20 000 каждого вида | Защитный потолок массивов — 200 000 каждого вида |
| Суммарный пользовательский текст | 3 МиБ | Ограничен размером снимка |

Большие пределы кодека не означают, что файл примет Android-приложение.
Границы включительны. Из лимита контейнера вычитаются заголовок и GCM-тег:
при 50 МиБ JSON занимает не более 52 428 742 байт в `OTMB1` и 52 428 718 в `OTMP1`.
`BackupLimits` может только уменьшить лимиты байтов и интервалов: `maxBytes > 0`,
`maxSegments >= 0`.

Размер, длина и фиксированный KDF проверяются до вывода ключа. Массивы JSON
ограничены потоковым чтением; меньший `maxSegments` применяется до создания
доменных сегментов. Импорт дополнительно проверяется перед предпросмотром
и на границе записи в Room.

| Ошибка кодека | Причина |
| --- | --- |
| `MagicError` | Неизвестная или неполная сигнатура. |
| `VersionError` | Неподдерживаемая версия контейнера. |
| `IntegrityError` | Неверный пароль, повреждение `OTMB1`, неверные длина или KDF. |
| `PlainIntegrityError` | Неверные заголовок, длина или сумма `OTMP1`; пароль здесь не участвует. |
| `LimitError` | Превышен лимит ресурсов. |
| `SchemaError` | Неверная JSON-схема или связи данных. |

На уровне Android этим соответствуют `INTEGRITY`, `PLAIN_INTEGRITY`, `LIMIT`,
`INVALID_FORMAT`, `UNSUPPORTED_VERSION` и `IO`. `PASSWORD_REQUIRED` означает,
что файл `OTMB1` открыли через действие без пароля, а не разрешение обойти защиту.
Неверный пароль и GCM-тег неразличимы по типу и сообщению ошибки.
В ошибки не включаются пароль, заметки или названия; частичные данные не возвращаются.

## Контрольный тестовый вектор OTMB1

Независимый вектор рассчитан через Python `hashlib.pbkdf2_hmac` и `AESGCM`
из `cryptography`. Это тестовые, не рабочие значения:

- Пароль: `fixture-password`.
- Соль: `000102030405060708090a0b0c0d0e0f`.
- Nonce: `101112131415161718191a1b`.
- JSON: 79 байт.

```json
{"schemaVersion":1,"projects":[],"entries":[],"segments":[],"activeEntry":null}
```

Реализация: [BackupCodec](../core/src/main/kotlin/dev/opentimemanager/core/backup/BackupCodec.kt),

## CSV

`CsvExporter.write(Sequence<ExportRecord>, Appendable)` записывает закрытые
интервалы в порядке входной последовательности. Вызывающий код выбирает UTF-8.
Даже пустой экспорт содержит один заголовок:

```text
segment_id,entry_id,project_id,project_name,start_utc,end_utc,zone_id,duration_seconds,note,source
```

- Разделитель — запятая, конец строки — CRLF, правила кавычек — RFC 4180.
  Запятая, кавычка или перевод строки требуют двойных кавычек; внутренние
  кавычки удваиваются.
- `start_utc`/`end_utc` — ISO-8601 UTC с `Z`, `zone_id` — исходный `ZoneId`.
- `duration_seconds` — точное десятичное число с точкой и до трёх дробных
  знаков, без группировки и лишних нулей.
- `source` — `TIMER`, `MANUAL` или `IMPORT`. Пустая заметка остаётся пустой ячейкой.
  BOM не добавляется.
- «Без проекта» записывается локализованным именем, а не маркером `@default`.
- Если первый непробельный символ текстовой ячейки — `=`, `+`, `-` или `@`,
  перед строкой добавляется апостроф до применения CSV-кавычек. Это касается и ID
  и снижает риск выполнения формул в таблицах. В копиях исходный текст не меняется.

CSV предназначен для анализа. Для восстановления нужен файл копии;
обычный рекомендуемый вариант — зашифрованный `.otmbackup`.

## English overview

This is the detailed format reference, written in Russian. Both containers carry
the same strict, versioned JSON snapshot, not a Room database. `OTMB1` uses
password-based AES-256-GCM; `OTMP1` is readable plaintext with a checksum that
does not prevent forgery. Detection uses file content and never falls back from
failed encryption to plaintext. Schema v2 is written; v1 remains readable.
Android limits are 4 MiB and 20,000 objects of each kind. CSV is UTF-8 spreadsheet
data, not a restorable backup. See the implementation links above for exact APIs
and the [English user guide](USER_GUIDE.md#backups-and-restore) for normal use.
