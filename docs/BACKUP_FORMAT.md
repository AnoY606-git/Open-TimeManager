# Формат переносимых данных Open TimeManager

Файл `.otmbackup` (`application/octet-stream`) содержит зашифрованный UTF-8 JSON
snapshot. Формат не является копией Room. Кодек работает с неизменяемыми
`PortableSnapshot`, `PortableProject`, `PortableEntry`, закрытыми `Segment`,
необязательной `PortableActiveEntry` и переносимыми настройками. Запись файла и замена данных в БД относятся
к вызывающему коду; сам кодек не изменяет хранилище.

## Решение и границы

Проблема: перенести проекты, записи, сегменты и незавершённое состояние без
зависимости от схемы БД и без автоматического запуска таймера после восстановления.
Выбран версионированный JSON внутри аутентифицированного бинарного контейнера.
Альтернативы: копия БД привязывает перенос к миграциям; открытый JSON не защищает
заметки; собственный бинарный payload усложняет независимое чтение. Цена JSON —
больший размер и временные аллокации при сериализации. Совместимость проверяют
независимый golden vector, roundtrip, тесты schema и ограничений.

## Контейнер

Порядок чисел — big endian. Заголовок занимает ровно 42 байта.

| Смещение | Размер | Значение |
| --- | --- | --- |
| 0 | 5 | ASCII `OTMB1` (`4f544d4231`) |
| 5 | 1 | Версия контейнера `01` |
| 6 | 4 | Число итераций PBKDF2, `310000` (`0004baf0`) |
| 10 | 16 | Случайная salt |
| 26 | 12 | Случайный nonce |
| 38 | 4 | Неотрицательная длина plaintext JSON в UTF-8 байтах |
| 42 | длина plaintext | AES-256-GCM ciphertext |
| после ciphertext | 16 | GCM authentication tag |

Версия 1 однозначно задаёт PBKDF2-HMAC-SHA256, 256-битный AES ключ,
AES/GCM/NoPadding и 128-битный tag. Другой алгоритм требует новой версии.
Произвольное число итераций из файла не исполняется: допустимо только 310000.
Все **42 байта заголовка** передаются GCM как AAD. Salt и nonce получают
из переданного `SecureRandom` последовательными запросами на 16 и 12 байт.
В рабочем приложении требуется обычный криптографически надёжный генератор;
детерминированный генератор используется только в тестах.

Пароль передаётся `CharArray` в `PBEKeySpec` и не преобразуется в `String`.
Кодек очищает собственную копию пароля в `PBEKeySpec`, массив выведенного ключа
в `finally` и временный plaintext массив после операции. Переданный пароль
принадлежит вызывающему коду и не меняется; UI должен очистить его после работы.
JVM и криптографический provider могут создавать внутренние копии данных;
полное уничтожение всех копий памяти не заявляется.

## JSON schemaVersion 2

Все ключи обязательны, включая `activeEntry: null`. Неизвестные ключи на любом
уровне, неизвестные значения source/state, невалидный UTF-8, неправильные типы,
дробные машинные целые, неверный ZoneId и лишние токены после JSON отклоняются.
Сериализация компактная, без BOM и пробелов между токенами. Порядок ключей при
экспорте показан ниже; порядок элементов списков сохраняется. При чтении порядок
ключей может отличаться. Инстанты и длительности записаны целыми миллисекундами,
независимо от locale; `startUtcMillis` — Unix epoch UTC.

```json
{"schemaVersion":2,"projects":[{"id":"a1234567-89ab-4cde-8fab-0123456789ab","name":"Работа","colorArgb":-15584170,"createdAtUtcMillis":0,"archivedAtUtcMillis":null,"isDefault":false}],"entries":[{"id":"b1234567-89ab-4cde-8fab-0123456789ab","projectId":"a1234567-89ab-4cde-8fab-0123456789ab","note":"","zoneId":"Europe/Moscow","source":"TIMER"}],"segments":[{"id":"c1234567-89ab-4cde-8fab-0123456789ab","entryId":"b1234567-89ab-4cde-8fab-0123456789ab","projectId":"a1234567-89ab-4cde-8fab-0123456789ab","startUtcMillis":0,"durationMillis":1000}],"activeEntry":null,"preferences":{"theme":"SYSTEM","dynamicColor":true,"privacyMode":true,"dailyGoalMinutes":480}}
```

`projects` хранит id, имя, ARGB-цвет, время создания, необязательное время
архивации и `isDefault`. Единственный canonical default имеет зарезервированный
UUID `00000000-0000-4000-8000-000000000001`, имя хранения `@default`,
`isDefault: true` и не архивируется. Пользователь видит локализованное имя, а не
маркер хранения. `entries` хранит id, projectId, заметку, исходный IANA/Java
ZoneId и source (`TIMER`, `MANUAL`, `IMPORT`). Каждый `segments` содержит id,
entryId, projectId, startUtcMillis и строго положительную durationMillis.
Конец сегмента вычисляется как `startUtcMillis + durationMillis` с проверкой
переполнения. Все project/entry/segment ID и все ссылки на них, включая
activeEntry, должны быть UUID в полной стандартной 36-символьной форме
`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. Проверка разбирает UUID и сравнивает
полную форму без учёта регистра; сокращённые группы, пропущенные дефисы,
не-hex символы и пробельные префиксы отклоняются как `SchemaError` при encrypt
и decrypt. Регистр исходного текста сохраняется, автоматической нормализации
ID или ссылок нет; ссылки должны совпадать с текстом определённого ID.
Сумма длительностей каждого entry вычисляется через `Math.addExact`; переполнение
отклоняется при создании backup, после аутентифицированного чтения и повторно на
границе Room restore. Общие конструкторы Domain ID этим форматом не ограничены. Повторяющиеся project/entry/segment id и
несуществующие ссылки отклоняются. projectId сегмента должен совпадать с проектом
его записи. Пустые имя/заметка допустимы; их исходный текст сохраняется.

`activeEntry` — `null` либо объект с ключами `entryId`, `projectId`, `state`.
Он явно обозначает незавершённую запись. Допустимы `RUNNING`, `PAUSED`,
`NEEDS_REVIEW`; `IDLE` не представляет активную запись. При импорте `RUNNING`
всегда преобразуется в `NEEDS_REVIEW`, `PAUSED` и `NEEDS_REVIEW` сохраняются.
Монотонные часы, boot count и открытый сегмент в формат не входят. Кодек не
добавляет длительность от момента backup до импорта и не создаёт runtime session.
Снимок RUNNING сохраняет только уже закрытые сегменты; вызывающий код отвечает
за подготовку снимка на выбранный момент и явное указание незавершённости.

`preferences` переносит `theme` (`SYSTEM`, `LIGHT`, `DARK`), `dynamicColor`,
`privacyMode` и `dailyGoalMinutes` (15–1440). Язык намеренно не записывается:
он остаётся framework locale Android/AppCompat на принимающем устройстве.

### Чтение schemaVersion 1

Контейнер `OTMB1` и его версия `01` не менялись. Reader продолжает принимать
payload schemaVersion 1 из независимого golden vector. Для отсутствующих полей
он использует безопасные детерминированные значения: стандартный цвет, createdAt
`0`, отсутствие архивации и настройки SYSTEM/dynamic/privacy с целью 480 минут.
Зарезервированный default UUID canonicalизируется в `@default`, включая старые
копии с именем «Без проекта». При Merge конфликт v1-проекта определяется только по
фактически представленному в v1 имени; синтезированные цвет и даты не сравниваются
с локальными метаданными. Writer всегда создаёт schemaVersion 2.

## Гарантии восстановления

Preview не потребляется при конфликте UUID, активном таймере, отмене или откате;
его можно повторно применить. Для Replace все Room-таблицы очищаются и заполняются
в одной suspend-транзакции порциями с cancellation checkpoints. Отмена после
начала удаления откатывает весь Room-граф. После успешного commit preview
считается применённым, даже если обновление системных поверхностей не удалось.

Merge проверяет число проектов в итоговом объединении внутри той же Room-транзакции
до первой вставки и оставляет preview доступным, если мобильный предел 20000 был бы
превышен. Зарезервированный default UUID обозначает одну canonical-сущность на
разных установках: при Merge его installation-specific `createdAtUtcMillis` не
участвует в сравнении, тогда как цвет и остальные переносимые инварианты schema v2
по-прежнему проверяются. Replace сохраняет переданную дату создания.

Room и Preferences DataStore — независимые хранилища, поэтому кросс-хранилищная
атомарность **не заявляется**. Replace записывает в той же Room-транзакции durable
journal с целевыми настройками, затем применяет одну DataStore edit и privacy
mirror. Если этот этап прерван, journal сохраняется и повторяется при следующем
старте. Гарантия — восстановимое схождение к настройкам backup после Room commit,
а не мгновенная атомарность двух механизмов хранения.

## Ограничения и ошибки

По умолчанию контейнер и plaintext ограничены 50 MiB (52428800 байт), сегменты —
200000. Из-за заголовка и tag максимальный plaintext экспортируемого файла
фактически равен 52428742 байтам. `BackupLimits` может уменьшить maxBytes и
maxSegments, но не увеличить эти потолки. maxBytes должен быть положительным,
maxSegments может быть нулевым. Равенство пределу допустимо.

Это hard limit переносимого формата и core-кодека, а не лимит Android UI.
Мобильное приложение намеренно задаёт меньшую операционную политику: контейнер
до 4 MiB, до 20000 проектов, записей и сегментов и до 3 MiB суммарного
пользовательского текста. Поэтому файл, допустимый для core-кодека, может быть
отклонён приложением до PBKDF2 или JSON parsing ради ограниченного расхода памяти.

Длина контейнера, объявленная длина plaintext и фиксированный KDF проверяются
до вывода ключа и копирования ciphertext. Plaintext проверяется до JSON parsing.
JSON-массивы ограничены 200000 элементами потоковым serializer: запись 200001
не создаётся. Такой же защитный потолок действует на проекты и записи.
Пользовательский меньший maxSegments проверяется после decode JSON DTO, до
построения предметных сегментов. JSON не сжат; распаковки не происходит.

Кодек выбрасывает наследников `BackupError`:

- `MagicError`: сигнатура не совпадает или для неё не хватает байт.
- `VersionError`: неизвестная версия контейнера.
- `IntegrityError`: неверный пароль, повреждение ciphertext/tag/поддерживаемого
  заголовка, усечённый контейнер, несовместимая длина или недопустимый KDF.
- `LimitError`: превышены ресурсные ограничения.
- `SchemaError`: аутентифицированный JSON не соответствует schema или инвариантам.

Неверный пароль и неверный GCM tag имеют одинаковые тип/сообщение ошибки без
provider-specific cause. Имена проектов, заметки, пароль и импортированные строки
не включаются в ошибки. Отказ не возвращает частично прочитанный snapshot.
Независимый криптографический аудит не проводился.

## Независимый golden vector

## CSV

`CsvExporter.write(Sequence<ExportRecord>, Appendable)` экспортирует закрытые
сегменты в порядке последовательности. Вызывающий код выбирает UTF-8 при записи
в файл. Включён ровно один стабильный заголовок, включая пустой экспорт:

```text
segment_id,entry_id,project_id,project_name,start_utc,end_utc,zone_id,duration_seconds,note,source
```

Разделитель — запятая, окончание записи — CRLF, цитирование — RFC 4180:
запятая, кавычка, CR или LF требуют двойных кавычек, внутренние кавычки удваиваются.
start/end — ISO-8601 UTC (`Z`), zone_id — исходный ZoneId. duration_seconds —
точное десятичное число секунд без группировки, с точкой и до трёх дробных знаков;
лишние нули убираются. source использует те же `TIMER`, `MANUAL`, `IMPORT`.
Пустая заметка остаётся пустой ячейкой. BOM не добавляется.

Canonical default project экспортируется в CSV с текущим локализованным именем
(`No project`/`Без проекта`), тогда как backup сохраняет canonical-маркер.

Текстовая ячейка, первый непробельный символ которой равен `=`, `+`, `-`, `@`,
получает ведущий апостроф до RFC 4180 quoting; это касается и ID. Исходные строки
остаются в backup без такого преобразования. CSV предназначен для анализа;
для точного восстановления используется зашифрованный snapshot.
