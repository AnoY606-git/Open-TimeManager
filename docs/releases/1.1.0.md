# Open TimeManager 1.1.0

**Upcoming stable release / Готовящийся стабильный выпуск** · `versionCode = 3`
Android 12+ (API 31) · Target API 36 · GPL-3.0-only

## Русский

Эти notes описывают изменения 1.1.0, но **не подтверждают публикацию, подпись,
прохождение CI, проверку OEM или выигрыш батареи**. До публикации 1.1 последняя
опубликованная стабильная версия — [1.0.0](1.0.0.md). Итоговые факты должны быть в
metadata рядом с окончательным APK на [странице v1.1.0](https://github.com/AnoY606-git/Open-TimeManager/releases/tag/v1.1.0).

### Что меняется

- Настройки открывают пять отдельных экранов: Оформление, Учёт и проекты,
  Копии данных, Как работать с приложением и О приложении.
- Поиск по подробному офлайн-руководству из десяти тем на русском и английском:
  от первой сессии до восстановления таймера, файлов и ограничений батареи.
- Локальный проект по умолчанию. Приоритет: активная сессия → явный выбор на
  свободном таймере → действующее предпочтение → безопасный fallback. Он не
  переключает сессию и не входит в переносимые настройки/schema. Быстрый старт
  виджета/плитки использует действующее предпочтение, иначе требует ровно один
  подходящий проект; при неоднозначности открывается приложение.
- Основное создание backup остаётся зашифрованным **`.otmbackup` / `OTMB1`**, с
  прежней schema v2 и чтением v1. Формат шифрования не меняется.
- Отдельный необязательный **`.otmplain` / `OTMP1`** использует тот же строгий
  payload schema v2 и лимиты, но **не шифруется и не аутентифицируется**. Создание
  требует предупреждения; импорт предупреждает о недоверенном файле. SHA-256 —
  проверка случайного повреждения, не защита от подделки. Ошибка зашифрованного
  файла не разрешает незаметно перейти к plaintext.
- Android 12: Material You, адаптивное представление виджета, preview/размеры в
  ячейках и ручное добавление плитки. Android 13+: per-app language и системный
  запрос добавления Quick Settings tile по нажатию. Pin-запрос виджета зависит от
  лаунчера; при отказе/отсутствии поддержки есть ручной путь.
- Стандартная страница приложения в настройках Android, только чтение признаков
  Battery Saver/фонового ограничения и справочные подсказки HyperOS/MIUI, One UI,
  ColorOS/OxygenOS/realme UI. Это не частная OEM-интеграция и не список проверенных ROM.
- Повторные одинаковые системные проекции отфильтровываются; на паузе уведомление
  показывает фиксированное подтверждённое время, resize статичного виджета не
  перечитывает Room. Новых counting timers, wake locks или alarm scheduler нет.
- Android 16: необязательный запрос Live Updates для запущенного таймера. По умолчанию выключен, скрытая пользователем сессия не продвигается повторно. Полный API зависит от системного обновления (36.1); базовый API 36 может оставить обычное уведомление. Решение о продвижении остаётся у Android и оболочки.
- Исправлены устаревшие изменения истории после Replace, смена часового пояса в открытом редакторе, зависание наблюдения настроек после I/O-сбоя и гонка архивации активного проекта. Предыдущие итоги отчёта не показываются под новыми датами; после импорта сообщается об ожидающей синхронизации приватности.

### Данные и границы защиты

Нет повышения minSdk, обязательного battery exemption или частного
Super Island/HyperIsland API. Для Live Updates добавлено обычное, не runtime-разрешение `POST_PROMOTED_NOTIFICATIONS`. Нет `INTERNET`,
аккаунта, рекламы или аналитики; automatic Android backup остаётся отключённым.
Системные возможности зависят от версии Android, лаунчера, разрешений и прошивки.
Экономия батареи **не измерена**, проценты или дополнительные часы не обещаются.

**`.otmplain` и CSV — открытый текст.** Их получатель может читать содержимое;
открытую копию также можно незаметно изменить, пересчитав checksum. Структурно
проверенный предпросмотр не доказывает автора. Шифрование `.otmbackup` не шифрует
локальную Room-базу. Язык и локальный default project не переносятся ни одним
backup. Копии сохраняют закрытые подтверждённые интервалы, не текущий открытый
отрезок: сначала поставьте таймер на паузу или завершите его.

Android-пределы остаются **4 МиБ и 20 000 проектов, записей и сегментов каждого
вида**. Restore блокируется при запущенном, приостановленном или требующем проверки
таймере. Успешный Replace необратим: сначала создайте отдельную проверенную
зашифрованную копию. Один atomic commit между Room и DataStore не заявляется.

## English

These notes describe 1.1.0 changes, **not proof of publication, signing, CI success,
OEM testing, or battery improvement**. Until publication, [1.0.0](1.0.0.md) remains
the published stable version. Final facts belong to the assets beside the final
APK on the [v1.1.0 page](https://github.com/AnoY606-git/Open-TimeManager/releases/tag/v1.1.0).

### Changes

- Settings opens five focused screens: Appearance, Tracking and projects,
  Backups and restore, Help, and About.
- A searchable, detailed ten-topic guide works offline in English and Russian,
  including timer recovery, file safety, system controls, and battery restrictions.
- Local-only default-project selection: active session → explicit idle choice →
  valid preference → safe fallback. It never switches an active session and is
  outside portable preferences/schema. Widget/tile quick Start uses a valid
  preference, otherwise exactly one eligible project; ambiguity opens the app.
- **Encrypted `.otmbackup` / `OTMB1` stays the default**, retaining schema v2,
  v1 readability, and its existing encryption format.
- Optional **`.otmplain` / `OTMP1`** uses the same strict schema v2 payload and
  limits, with **no encryption or authenticity protection**. Separate create and
  untrusted-import warnings explain the risk. SHA-256 detects accidental damage,
  not forgery. Encrypted-file failures do not silently authorize plaintext fallback.
- Android 12 Material You, responsive widget presentation with preview/cell sizing,
  and manual tile addition. Android 13+ per-app language and user-triggered system
  Quick Settings tile-add requests. Widget pinning depends on launcher support,
  with manual fallback instead of a placement guarantee.
- Safe application-details settings, read-only Battery Saver/background-restriction
  status, and advisory HyperOS/MIUI, One UI, ColorOS/OxygenOS/realme UI hints—not
  private OEM integrations or evidence of testing every ROM.
- Equal event-driven system projections are filtered; paused notification time
  stays fixed, and static widget resize does not reread Room. No counting timer,
  wake lock, or alarm scheduler is added.
- Optional Android 16 Live Updates request prominent presentation for a running timer. Off by default; a dismissed session is not promoted again. The complete API depends on the system update (36.1); base API 36 may retain normal presentation. Android and the OEM decide promotion.
- Fixed stale history mutations after Replace, time-zone changes during editing, settings observers completing after I/O failure, and archive/start races. Old report totals are hidden while a new range loads; committed imports report pending privacy/preference convergence.

### Data and limitations

No higher minimum SDK, required battery exemption or private
Super Island/HyperIsland API. Live Updates add the normal, non-runtime `POST_PROMOTED_NOTIFICATIONS` permission. No network permission,
account, ads, or analytics; automatic Android backup remains disabled. Native
controls depend on Android, launcher, permissions, and firmware. **Battery savings
are unmeasured**; no percentage or extra-hours claim is made.

**`.otmplain` and CSV are plaintext.** Anyone holding an unprotected copy can read
or modify it and recompute its checksum; structural inspection is not proof of
authorship. Encrypted backup does not encrypt the local database. Language and
the local default project are not transferred in either format. Copies include
confirmed closed intervals, not the current open interval: pause or stop first.

Android limits remain **4 MiB and 20,000 projects, entries, and segments each**.
Restore is blocked for running, paused, or review sessions. Successful Replace
has no Undo: first create a separately verified encrypted copy. One atomic
Room/DataStore transaction is not claimed.

### Updating and provenance

The intended update keeps 1.0's production key and existing data. Actual final
certificate comparison and an in-place upgrade test must establish this result.
**Never uninstall, clear app data, or downgrade to force a signing mismatch.**
Preview/debug may use another key; stop and plan a separate migration with a
verified backup if signatures differ.

Expected final assets are `Open-TimeManager-1.1.0.apk`, `SHA256SUMS`,
`SIGNING_CERT.txt`, `SOURCE_COMMIT.txt`, `Open-TimeManager-1.1.0-source.tar.gz`, and
`VERIFICATION.md`. They must identify the actual signed bytes, public certificate,
matching source/tag, real test/upgrade results, and unperformed scenarios. No
hashes or success results are invented in advance. Debug/unsigned CI APKs are not
the production release. Recipients must be able to obtain Corresponding Source.
This is not a Google Play release or an independent security audit.
